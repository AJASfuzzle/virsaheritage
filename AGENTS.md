# Architecture rules
- Echoes search filters posts before pagination through the caller's RLS-scoped client, and uses URL search state plus a shared literal matcher for public display-only seeds, so search never expands access.
- Keep Kitab entries and filter logic in the shared catalogue and derive all displayed language totals from it, so archive and homepage counts cannot drift; new facts retain source URLs and unsupported fields stay absent.
- Global localization uses the root LanguageProvider and AutoTranslator; track originals per Text node rather than per parent to preserve mixed inline content.
- Translation jobs and caches are keyed by language; never cache failed English fallbacks as successful translations.
- Keep Google Translation as the primary service with a streamed Lovable AI fallback for unsupported languages or unavailable quota; enforce each language's script server-side.
- VIRSA Cam device calls hit the TanStack server route /api/public/virsa-cam (x-device-key checked); page actions use server functions in virsa-cam.functions.ts, because this stack forbids Supabase Edge Functions.
- VIRSA Cam is owner-only: camera_devices pairs the device to one user; RLS on camera_status/requests/captures/messages scopes to owner/user_id; uploads inherit the user of the request they fulfil; live view is opt-in (preview_until heartbeat); preview frames are never stored, only relayed over a private broadcast topic cam-preview-<device id> (owner-only realtime policy); ?mode=preview doubles as the poll; speech plays server-generated audio through one persistent audio element.
